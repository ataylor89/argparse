* Final remarks:

You can see, from the example usage, that the BuilderPattern class works just as well as the AddSubtract2 class.

The two classes are very similar... but the key difference is that the BuilderPattern class uses the builder pattern to create Option objects and to add them to the Options container.

The AddSubtract2 class, on the other hand, uses the Options#addOption method.

The Options#addOption method can save the programmer time and code if the option is not too complex.

But it can also become a little messy, when the option is really complex.

The Option.builder() approach can take a little more time, and a little more code, than the former approach.

But it is often more organized and easier to read, especially when the option we are dealing with is really complex.

In conclusion, it's nice to have both approaches.

We can use whichever approach is more suited to the task at hand.

This way, we have the best of both worlds.

I look forward to adding more features, in the future :)

Wednesday, November 4, 2026 - Thursday, November 5, 2026

* I added Xor.java
* Xor.java is an XOR cipher... it uses the XOR operation to encrypt or decrypt a message
* It was used over 100 years ago, in 1917, by Gilbert Vernam
* It is based on the fact that xor(xor(m)) = m, just like rot13(rot13(m)) = m
* XOR is a symmetric key algorithm, which means the encryption key and the decryption key are the same
* XOR is a relatively secure algorithm
* XOR is secure, so long as your key is secret
* But if someone discovers your key, then the algorithm is not secure
* For this reason, people study the problem of how do you share an xor key in a secure way
* The RSA algorithm is attractive because, if your public key is discovered, then cracking the message is still difficult
* But if you use the XOR algorithm, and your key is discovered, then cracking the message is trivial
* Thus XOR depends on keeping the key a secret
* Example usage:

    # cd into the src directory
    % cd ~/Github/argparse/src

    # Compile the Java source code into bytecode
    % javac Xor.java argparse/*.java

    # Encrypt a message using the XOR algorithm, and use "testkey" as our secret key
    # Also, use base64 encoding, just so that the output is easy to read, copy, and paste
    % java Xor "hello world today is thursday november 5 2026" -k "testkey" -e -b64
    HAAfGARFDhsXHxBLERYQBApUAhZZAA0GBhgBGA1FHRsdABQWAAFUXkVLRFdF

    # Encrypt a message using the XOR algorithm, use "testkey" as our secret key, and write the output to cipher.txt
    # Once again, use base64 encoding
    % java Xor "hello world today is thursday november 5 2026" -k "testkey" -e -b64 -of cipher.txt

    # Decrypt a message using the XOR algorithm, use "testkey" as our secret key, and read the input from cipher.txt
    # Also, use base64 decoding, because the encrypted message is encoded in base64
    % java Xor -if cipher.txt -k "testkey" -d -b64
    hello world today is thursday november 5 2026

* I added Primegen.java
* Primegen.java is a program (and library) that generates prime numbers
* You can call the Primegen#generate(int) method, and pass it an integer n, to generate the first n prime numbers
* Behind the scenes, it uses the Primegen#sieve(int) method, to generate a sieve of a specified size
* The sieve is used to separate prime numbers from composite numbers
* The algorithm for creating the sieve is often referred to as the Sieve of Eratosthenes
* In my opinion, a sieve is a filter
* A filter is a device that separates an input stream into two categories: what gets filtered in and what gets filtered out
* The boolean array, named sieve, has true and false values, which are used to indicate what's prime and composite
* For example, sieve[2] is true, because 2 is a prime number, but sieve[4] is false, because 4 is not a prime number
* The numbers 0 and 1 are neither composite nor prime, so I set sieve[0] and sieve[1] to false
* To give some more examples, sieve[3] is true, because 3 is a prime number, and sieve[10] is false, because 10 is composite

* Final remarks:

I'll be using Primegen.java to generate primes for my implementation of the RSA algorithm.

The RSA algorithm is based on prime numbers.

In the RSA algorithm, we choose two prime numbers, p and q, that satisfy the following requirements:

(1) p and q are distinct prime numbers
(2) p and q are large enough that their product is difficult to factor

We use the variable n to denote the product of p and q.

In other words, n = p * q.

The number n is a semiprime. A semiprime is the product of two prime numbers.

The number n gets used as the modulus in the formula c = m^e (mod n).

In the formula, above, m is the code point of a Unicode character, e is the encryption exponent, n is the modulus, and c is the cipher.

The formula for encrypting a character of text is c = m^e (mod n).

The formula for decrypting a cipher is m = c^d (mod n).

In the second formula, involving d, the variable d is the decryption exponent, c is the cipher, n is the modulus, and m is the code point of the original character.

It so happens that m = (m^e)^d (mod n).

This is actually a consequence of Euler's totient theorem.

The encryption and decryption exponents, e and d, are chosen to satisfy the property that m = (m^e)^d (mod n).

The public key is the tuple (n, e), in which n is the modulus and e is the encryption exponent.

The private key is the tuple (n, d), in which n is the modulus and d is the decryption exponent.

To make RSA more secure, we can make the public key a list of (n, e) tuples, similar to what we do in AddSubtract2.

Likewise, we can make the private key a list of (n, d) tuples, similar to what we do in AddSubtract2.

The algorithm for generating the n, e, and d values is described in the paper "A Method for Obtaining Digital Signatures and Public-Key Cryptosystems" by R.L. Rivest, A. Shamir, and L. Adleman, published in 1978.
